## 1. Duo and Grand Prix Power never appear in the Library (all builds)

**Found by:** the public-build check (`docs/pending/public-chip-art.md`). **Analysed by:** Claude, in the decomp.

- **The Library lists only chips with bit `0x40` of chip byte `+9` set.** The listing loops are in `code_03`, e.g. `sub_08037798` for Standard. Duo (`0x137`) and GP Power (`0x138`) have it clear in both US ROMs, as e-Reader chips did. So players can get both chips, but they never show in the Library.
- **That bit is identical in the RS and BM tables** (288 chips listed in both). The other version's chips are already listed.
- **The Library counts behind the completion stars** are `GetLibraryCountStandard` / `Mega` / `Giga` / `PA` (`0x080373A8`…`0x080374F0`):
  - they count owned chips with bit `0x40` set;
  - they skip chips with byte `+0x16` bit `0x01`;
  - they skip the other version's chips: byte `+0x16` bit `0x04` in one version, `0x08` in the other (`VERSION_INDEX`).
- **The stars compare with exact equality** (`GetCompletionStars`, `cmp r0, #0x3c; bne`): Standard 150, Mega 60, Giga 5, PA 30. Listing Duo (Giga) and GP Power (Mega) the plain way would make those counts 6 and 61, and **lose the stars**.
- **~~Proposed fix~~: not safe, superseded by `docs/tests/library-flags.md` (batch 4, `e565508`).** Setting `+9` bit `0x40` plus `+0x16` bits `0x04 | 0x08` keeps the stars exact, but the chips **still don't appear**, for two reasons:
  - the Mega and Giga *listing* loops (`sub_08037824`, `sub_080378D8`) skip chips with the other version's bit too. Claude had checked only the Standard loop, which has no version filter;
  - the listings map each chip's Library number (291 GP Power, 292 Duo) through a 300-entry slot table, and those entries are 0 in both versions. The write would land just before the buffer.

  Showing them needs:
  - new slot-table entries in both versions (Mega slot 61, Giga slot 6);
  - listing filters they pass;
  - Library count functions changed so the stars still need exactly 60 Mega and 5 Giga.

  Also, `sub_08030754` (a give-all-chips routine, ids `0x138`..1) would hand out 30 copies of each code if bit `0x40` were set without the version bits. **Not verified:** whether the Library screen's page count and cursor limits assume exactly 60 and 5 slots.
- **Owner question:** should Duo and GP Power appear in the Library? They aren't part of the original star counts either way.

## 2. Frequency Tuner: the text box may stay stuck after "Yes"

**Found by:** the smoke test (`patch/test/smoke/`, Red Sun).

- After talking to the Tuner in Higsby's and choosing Yes, flag `0x0E58` is set (the mode changes), but the text box stays open and empty, and A or B don't close it.
- The Tuner never got past Tier 1 in those runs.
- **Could be a real soft-lock after `FC 0B 00`** (`wp_b2_frequency_tuner.asm`), or an artefact of headless input timing.
- Gemini's round-11 test only checked the flag toggle. **Needs an in-game look** (the PC port, windowed).

## 3. Status screen page 3

**Found by:** the smoke test.

- **Page 3 appeared with only 9 or 11 Souls owned.** The package says page 3 shows only once a 13th Soul is owned (`wp_d4_status_two_pages.asm`: R skips page 12 when `SOUL_BUF[12]` is `0xFF`).
- **With flag `0x23` set by a save edit, page 3 stayed blank, with no Duo icon.** The save edit may not set everything the screen reads, e.g. the Soul's chip key.
- Gemini's round-11 test with all 13 Souls (`patch-test-results-7-c1-c5.md` C1) showed the Duo emblem. **Needs an in-game look** with 11 and with 13 Souls, from a real game rather than a save edit.
