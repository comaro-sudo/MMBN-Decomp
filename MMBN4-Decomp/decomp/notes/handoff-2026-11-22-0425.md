### Continuation update: conservative short callback tables

`tools/survey.py` now accepts a two- or three-entry ROM-pointer run only when
every target begins with Thumb `push {..., lr}` and the target is currently
undecoded rather than a literal-pool word. This is deliberately narrower than
the existing four-or-more entry pointer-table rule, but reaches common state
and callback tables without promoting isolated pointer-shaped data to code.
The complete rationale and reproduction steps are in
[dc2-short-pointer-tables.md](dc2-short-pointer-tables.md); the remaining
indirect-flow work is tracked in [dc2-dispatch-worklist.md](dc2-dispatch-worklist.md).

## Safe continuation workflow

The Capstone dependency is installed only in WSL's documented venv. Plain `python3` in WSL does not have it.

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd /mnt/c/proyectos/MMBN-Decomp/MMBN4-Decomp/decomp && ~/.venvs/mmbn4-decomp/bin/python tools/disasm.py bm code_04"
```

For an RS segment, replace `bm` with `rs`. The command:

1. regenerates one source file;
2. iteratively emits problematic instructions as raw values when needed; and
3. verifies that segment against the selected baserom.

Always finish a change with both complete checks:

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd /mnt/c/proyectos/MMBN-Decomp/MMBN4-Decomp/decomp && make -B compare VERSION=rs && make -B compare VERSION=bm"
```

2. Work bounded gaps in `code_05`, then `code_04` and `code_06`; their main

5. Keep all ROM-derived opaque data as `incrom`/`.incbin`. No baserom bytes or extracted assets may be committed.
